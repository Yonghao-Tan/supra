# Fixed Hardware Tests

Start with `head_state_update_32tokens/case.json` using `scripts/run_testcase.py`.
The initial DDR image and independent expected bytes are provided; no generation step is required.

`control/` contains fixed numeric/state records for the optional control regressions.
Expected selections and state transitions are generated by the algorithm functions
from the supplied candidate scores and dependencies. These records are consumed
by the hardware tests without loading a model.

`control/psme_state_updates.json` supplies synthetic inputs and algorithm
reference values for DVSC state transitions. The regression compares RTL
and C-model outputs against these values.

With the algorithm environment installed, regenerate the small fixture from the
release root into a new output file:

```bash
python -B integration/hardware_adapter/control_reference_data.py \
  --kind psme-state-updates --index "$SUPRA_ARTIFACT_ROOT/psme_state_updates.json"
python3 -B hardware/scripts/run_unit_tests.py --case psme \
  --feature2-reference "$SUPRA_ARTIFACT_ROOT/psme_state_updates.json" --run-id generated-feature2
```

For model-derived inputs, follow the capture and preparation commands in
`integration/README.md`. Regular preparation connects the observed control
records automatically. To run the DVSC check separately, extract a control reference:

```bash
python -B integration/hardware_adapter/control_reference_data.py \
  --kind captured-feature2 \
  --input "$SUPRA_ALGORITHM_ROOT/sequence/index-step-layers.json" \
  --index "$SUPRA_ARTIFACT_ROOT/control.json"
python3 -B hardware/scripts/run_unit_tests.py --case psme \
  --feature2-reference "$SUPRA_ARTIFACT_ROOT/control.json" --run-id captured-control
```

`uaps_retry_prediction_target/case.json` checks UAPS selection following head
and state updates; its `suppressed/` variant covers token suppression. Both use
LPDDR4-3200 and compare complete 2 MiB DDR images. See the
[case guide](uaps_retry_prediction_target/README.md) for commands and input sources.

## Continuous testcase

These public cases use zero Transformer weights and synthetic C11 control inputs. Run them through `scripts/run_testcase.py` with a fresh run ID.

| Entry | Ordered executions |
|---|---|
| `in_block_handoff/case.json` | L31, post-processing, next L0 |
| `cross_block_handoff/case.json` | L31, post-processing, full 164-token L0 scout, 80-token L1 deep selection |

Later executions consume actual state and hidden output. Checks observe accepted embedding reads and compare independent scout scores, deep metadata and selected persistent cache bytes. Host `initial_segments`, copies and state packing are outside accelerator cycle counts.
